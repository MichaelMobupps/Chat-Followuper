Behavior:
1. SDR clicks Sign in with Google in the dashboard
2. Lands on Google consent screen
3. After approval, redirected back to /api/auth/google/callback
4. Server exchanges the code for tokens, fetches user identity (email, name,
   sub), upserts a row in users table keyed by Google email
5. Restrict logins to @mobupps.com only. Reject other domains with a clean
   error page on the dashboard side. Make the allowlist configurable via
   ALLOWED_LOGIN_DOMAINS env var, default 'mobupps.com'
6. Issue a signed session cookie, valid 30 days
7. /api/auth/me returns { id, email, name } when logged in, 401 when not
8. /api/auth/logout clears the cookie
9. AuthGate component redirects unauthenticated visitors to /login,
   wraps every page in App.tsx except /login itself

OAuth scopes: ONLY identity. openid, email, profile. Do NOT request
gmail.send, gmail.readonly, or any Gmail API scope. This is identity-only.

Scope reduction matters: this app does not send Gmail. The previous
Email Followuper tool requested gmail.send. Phase 1 of this tool does
not. Keeping scopes minimal avoids unnecessary consent friction and
keeps the consent screen clean.

Acceptance criteria:
1. Visit dashboard at /, see redirect to /login because no session
2. Click Sign in with Google, complete consent, land in dashboard
3. GET /api/auth/me returns { id, email, name } after login
4. A row exists in users table for the logged-in SDR with the correct email
5. Trying to log in with a non-@mobupps.com Google account is rejected
   with a clean error page (not a stack trace)
6. Visit /api/auth/logout, session is cleared, redirected to /login
7. Session cookie is HttpOnly, Secure (in prod), SameSite=Lax
8. AuthGate prevents direct URL access to /today, /seeder, etc when
   unauthenticated — redirects to /login
