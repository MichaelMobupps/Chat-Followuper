ADAPTATION RULES:

1. messageSummarizer.ts — adapted from emailSummarizer.ts:
   - Same job: extract topic + language from prior context
   - Same META_PARTICIPLES list, same sanitizer
   - Same language detection fallback (Unicode range checks)
   - Field shapes unchanged: { summary, language }
   - The system prompt stays focused on extracting a SHORT NOUN PHRASE
     suitable for "following up on the [TOPIC]" — not chat-specific yet,
     this is upstream of channel selection

2. messagePrompts.ts — adapted from followupPrompts.ts:
   - Remove ALL subject-line generation
   - JSON output schema becomes { "message": "..." } NOT { "subject": "...", "body": "..." }
   - Inject buildWriterRegisterBlock(channel) AFTER buildNativenessBlock(language)
     in both the writer system prompt and the rewriter system prompt
   - Critic gets a NEW score: channel_register_match (1-5)
   - Add channel_register_match to the forced-rewrite logic the same way
     language_match works: score below 3 forces needs_rewrite = true
   - Keep the META-LANGUAGE absolute prohibition unchanged
   - Keep the FOLLOW-UP ACK rule for stages >= 2 unchanged
   - Keep the WHY -> VALIDATION -> HOW -> DIFFERENTIATOR -> CTA structure
     for initial messages, but compress dramatically for chat (the register
     block enforces this)

3. messageGenerator.ts — adapted from followupGenerator.ts:
   - Same three-stage pipeline: draft (Sonnet) -> critic (Opus) -> rewrite (Sonnet)
   - Same self-healing loop with bestOverall tracking, max 3 iterations
   - Same humanizeText post-processor (em-dash strip, AI-tell phrase replacement,
     smart-quote normalize, !-to-period)
   - Same META-LANGUAGE detection and resanitizeStoredSummary self-heal
   - Function signature changes:
     generateChatMessage({
       prospect: ProspectRow,
       conversation: ConversationRow[],   // full thread, oldest to newest
       channel: 'whatsapp' | 'telegram' | 'teams' | 'slack',
       stage: number,
     }) -> {
       message: string,
       modelMetadata: { drafts, criticScores, iterations },
       costEstimate: { inputTokens, outputTokens, usd },
     }
   - costEstimate is rolled up across ALL stages (summarize + draft + critic +
     rewrite). Use the lib/pricing.ts pricing table from Ticket 1.11; create a
     stub now if it doesn't exist yet:
       export const ANTHROPIC_PRICING = {
         'claude-opus-4-7':    { input: 15.00, output: 75.00 },
         'claude-sonnet-4-6':  { input:  3.00, output: 15.00 },
         'claude-haiku-4-5':   { input:  0.80, output:  4.00 },
       };
   - CRITICAL: do NOT include a hardcoded multilingual fallback template.
     If Anthropic is unreachable, throw with a clear error message. The
     scheduler in Ticket 1.8 will mark the followup as 'failed' with the error.
     This is non-negotiable per Phase 1 cross-cutting rule 5.

4. channelRegister.ts — NEW file, mirrors the architecture of languageNativeness.ts:
   - Export buildWriterRegisterBlock(channel) and buildCriticRegisterBlock(channel)
   - Each returns the literal text appended to the prompt
   - Phase 1 implements the WhatsApp register fully; the others return
     placeholder strings noting "channel not yet supported in Phase 1"

   WhatsApp writer register text (this is the initial draft — will tune later):

   WHATSAPP CHANNEL RULES:
   - Length: 2-3 sentences MAXIMUM. Anything over 4 sentences feels like spam.
   - No subject line. No signature. WhatsApp shows your name automatically.
   - Greeting: "Hi {FirstName}," or omit entirely. Never "Dear", never
     "Good morning", never "I hope this finds you well".
   - Tone: real human typing on a phone. Casual-professional.
   - Emojis: 0 in conservative markets (Japan, Korea, Germany, Nordics, Russia).
     0-1 in friendly markets (LATAM, India, SEA, Middle East).
   - Banned phrases: "circling back", "touching base", "hope you are well",
     "I trust this finds you well", "would love to".
   - One soft CTA. One question mark maximum.
   - Plain text only. No bullet lists. No bold/italic markdown. WhatsApp's
     *bold* syntax is allowed only for emphasizing one short word, never
     for headers.
   - For follow-ups: reference prior contact in the first sentence. Keep it
     brief: "Following up on the MAFO numbers I sent" not "Following up on
     my detailed pricing breakdown for MAFO that I shared with you on
     April 24th".
   - No "X, not Y" constructions. Rephrase as positive specification.

   WhatsApp critic register text:

   Score channel_register_match 1-5 against the WhatsApp rules above.
   Score 5: 2-3 sentences, no signature, no formal opener, plain text,
            references prior contact (if follow-up), one CTA, one question mark.
   Score 1: Reads like an email. Multiple paragraphs. Formal greeting.
            Signature block. Multiple CTAs. Subject line attempted.
